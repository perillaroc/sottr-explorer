# 界面导览

应用按“先看整体，再逐层下钻”的顺序组织：

| 视图 | 回答的问题 | 主要内容 |
| --- | --- | --- |
| 概览 | 当前进度如何？ | 整体完成度候选、各区域完成情况、能力与限制说明；同一次会话内再次分析后显示与上一次的进度增量；可生成自包含的分享报告 |
| 全收集 | 100% 还差什么？ | 按必收口径列出缺失条目，区分故事/非故事、DLC 与挑战古墓；页头给出「必收指引 352/352」覆盖 |
| 收集计划 | 这次去哪里收？ | 只列未收集条目，按区域 → 子关卡 → 类别聚合；标出必收/可选、有底图/有文字下落，可打开地图、详情或逐条攻略，并导出可打印清单 |
| 区域与收集 | 这个区域里有什么？ | 区域 → 类别 → 条目逐层展开，标出已收集/未收集、子关卡与获取方式 |
| 详情 | 这一条怎么拿？ | 状态徽标、合集、获取方式或合集/子关卡指引、外部攻略、同子关卡相对位置 |
| 诊断 | 这个结论凭什么？ | 原始证据、数据来源、规则与诊断码 |
| 地图查询 | 东西都在哪？ | 底图 + 类别图标标记，与清单/详情联动 |
| 设置与关于 | 数据是什么版本？ | 界面偏好、图鉴版本、契约版本、第三方声明 |

## 存档监视提示

应用只读监视当前选中的存档。检测到游戏写入（更新，或原子替换导致文件身份变化）后，
页面顶部出现「当前存档已更新」提示；只有点「刷新」才会重新分析，应用不会自动分析。
文件暂时不可读时提示会说明原因并继续只读重试；文件已被删除或移走时提示重新选择。
切换存档、重新分析或关闭窗口时，监视器会重置/停止。

## 状态不是单一徽标
界面会同时呈现三类信息，它们相互独立：

- **观测**：存档里是否出现了这个 ID；
- **评估**：据此得到的“可能已收集 / 可能缺失 / 未知”；
- **证据等级**：这个判断是直接观察、社区关联，还是经游戏内验证。

因此“ID 出现”不等于“已收集”，“差集为空”也不等于全游戏完成。术语的严格定义见
[术语表](/reference/glossary)与[契约](/contracts)。

## 诊断页

诊断页承接原先散落在详情里的证据：表位置、参考集、组计数、来源链接与稳定诊断码。
界面只看诊断码与严重级别，不解析自然语言消息。错误码说明见[错误码与诊断](/reference/errors)。
