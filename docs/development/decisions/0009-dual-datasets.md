# ADR-0009 双数据集：catalog 与 metadata 分开

> 状态：已采纳（长期有效）。来源：[全收集图鉴](/data/catalog)、[收集品元数据](/data/metadata)。

## 背景

图鉴（名称、位置、获取方式）与元数据（内部 ID、区域计数、参考集合、攻略组）来源不同、
更新节奏不同、被不同的消费者使用。合并成一份表会让字段耦合、难以演进。

## 选项

| 选项 | 说明 | 结果 |
| --- | --- | --- |
| 拆成 catalog + metadata | 各自版本化，引用必须可解析 | **采纳** |
| 合并成单一大表 | 修改一处就要连带迁移另一侧字段 | 拒绝 |

## 决定

- **catalog** 负责图鉴条目、位置与获取方式；
- **metadata** 负责内部 ID、区域计数、参考集合与攻略组，并附 `manifest.json` 内容哈希。

两者由 manifest 哈希与测试互相锁定，避免漂移。

## 后果

- 跨数据集的引用（来源、类别、区域、组、参考集合、计数键）必须可解析，否则加载失败。
- 构建脚本提供 `--check`，校验现有文件与 manifest 一致。
- 修改任一数据集都要同步另一侧的引用与哈希清单。
