# 界面语言与文案资源

> 界面文案集中在资源文件，调用点只写键名；新增语言只改资源与注册表。

## 资源位置

| 文件 | 作用 |
| --- | --- |
| `apps/desktop/src/app/locales/zh-CN.ts` | 权威键表；`MessageKey` 由它推导，拼错键名会在编译期报错 |
| `apps/desktop/src/app/locales/en.ts` | 同一套键的英文；`Partial<Record<MessageKey, string>>`，缺失即回退 |
| `apps/desktop/src/app/locales/index.ts` | 注册表：`localeResources`、`LOCALES`、`LANGUAGE_OPTIONS` |
| `apps/desktop/src/app/i18n.ts` | 取值函数、缺失记录、`<html lang>` 同步 |

## 键命名

`命名空间.语义名`：命名空间来自首次出现该文案的模块（如 `collectionPage`、`store`）；跨三个以上模块复用的归到 `common`。语义名取英文、去标点、最多 7 个词。

静态标签表不写文案，只写键：

- `category.*`、`subcategory.*`：图鉴类别与故事子类别
- `region.*`：元数据缺英文名时的备选区域名
- `reason.*`：稳定原因码
- `source.*`：来源 ID
- `recoveryHint.*`：命令错误码的恢复建议

图鉴、区域、子关卡、获取说明等**数据自带 `zh`/`en` 字段**，继续走 `localizedName`，不进资源文件。

## 取值函数

| 函数 | 用途 | 对照模式（`both`） |
| --- | --- | --- |
| `t(key)` | 普通静态文案 | `中文 / English` |
| `tFormat(key, values)` | 模板里嵌**已本地化**的动态内容（区域名、条目名） | 只渲染中文模板，避免同一名称出现两次 |
| `tFormatPair(key, values)` | 模板里嵌**与语言无关**的值（路径、计数、错误消息） | 中英两种模板并列 |
| `localizedName(zh, en)` | 数据里的名称对 | 两种语言并列 |

## 回退与记录

- 英文缺失时回退中文；`missingTranslations()` 返回形如 `en:common.cancel` 的列表，开发模式下每个键只告警一次。
- 新增键必须同时补英文，`tests/i18n-resources.spec.ts` 会检查覆盖。
- 占位符用 `{name}`；渲染时找不到对应值会保留 `{name}` 原样，便于发现模板错误。

## 新增语言

以日语为例：

1. 复制 `locales/zh-CN.ts` 为 `locales/ja.ts`，导出
   `export const ja: Partial<Record<MessageKey, string>> = { ... }`。
2. 在 `locales/index.ts` 加三处（同一个文件，就是“一个注册项”）：
   - `localeResources` 加 `ja`；
   - `LOCALES` 加 `{ code: "ja", htmlLang: "ja", label: "日本語" }`；
   - `LANGUAGE_OPTIONS` 加一项（`label` 用语言自称，`hintKey` 用资源里的说明键）。
3. 跑 `pnpm test` 与 `pnpm build`；设置页的语言选项会自动出现。

`中英对照`（`both`）仍固定为中文 + 英文。

## 维护与门禁

- `tests/language.spec.ts` 覆盖中英行为，`tests/i18n-resources.spec.ts` 覆盖资源完整性、
  回退记录与模板语义。
- 门禁：`pnpm test`、`pnpm build`（含 `vue-tsc --noEmit`）。
