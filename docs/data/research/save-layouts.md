# 存档布局扩展（P3-5）

当前解析器只覆盖 4 MiB 战役家族；其他展开尺寸返回
`UNSUPPORTED_LAYOUT` / `UNSUPPORTED_CONTEXT`。本页记录 2026-11-18 的时间盒研究：
能否用现有样本扩展新布局。

::: warning 状态：否证（没有可扩展的新布局）
40 个样本里只有 4 MiB 战役布局与 25,600 字节的 `profile.dat`；
profile 按契约不进入战役语义。未知尺寸的提示已经明确，无需改产品。
:::

## 样本盘点

来源：公共 100% / Cozumel / NG+ 全 DLC 样本、私人战役样本、本机三个玩家目录
（含 `profile.dat` 与挑战古墓文件）。

| 布局 | 文件数 | 展开尺寸 |
| --- | --- | --- |
| 战役 4 MiB | **35** | 4,194,304 |
| profile | **5** | 25,600 |
| 其他 | 0 | — |

35 个 4 MiB 存档的主区段流全部走到声明终点：

| 指标 | 范围 |
| --- | --- |
| 主流长度 | 191,004 – 2,571,756 字节 |
| 区段数 | 25 – 6,784 |

覆盖进度 0.7%–100%、无 DLC / 全 DLC、NG+、挑战古墓文件与三个玩家目录，
**布局完全一致，变化只在内容长度与区段数。**

## profile.dat

- 展开固定 25,600 字节；0x10 处 `0xDEADBEEF`，0x28 处 `0x67`；
- 非零字段集中在 0x430–0x6xx，0x698 起有一大段 `0xFFFFFFFF`（疑似解锁位图）；
- 四个 profile 的差异集中在 0x230–0x290、0x430–0x4xx，没有可读字符串；
- 产品已把它标为“资料文件，仅容器观察”，不进入进度。

它不是战役存档的新布局，解析它也不会多出可展示的进度。

## 未知尺寸的用户可见行为

用一个解压后 2 MiB 的合成 blob 验证：

```text
container: supported
sections:  unsupported  UNSUPPORTED_CONTEXT  “主区段流校验失败（Unrecognized sample-family size）”
inventory: unsupported  UNSUPPORTED_CONTEXT  “区段流不可用…未执行记录恢复”
counters:  unsupported  UNSUPPORTED_LAYOUT
```

容器能解压，但区段、记录与计数器全部关闭，并给出明确原因；不会崩溃，
也不会伪造结论。

## 结论与所需数据

负向结项：现有数据里没有第二个战役布局。

若以后要继续，需要：

1. 其他游戏版本或平台的战役存档（展开尺寸不是 4 MiB），至少 2 个不同布局；
2. 若要把 profile 纳入产品，先定义 profile 的语义（解锁/设置/进度）；
3. 每个新布局至少一个最小夹具，覆盖成功与“长度非法 / 区段越界”两类错误。

## 复现

脚本留在开发工作区（`private/p3_5/layout_inventory.py`），只读存档副本与本机
存档目录，输出布局清单；未知尺寸样本与 CLI 验证命令见开发工作区报告。
